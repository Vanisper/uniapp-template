# 页面容器与导航约定

页面接入需要分别确定导航归属、导航栏提供者、底栏模式与滚动区域。这些职责在页面缓存、分包加载和平台切换后仍应保持一致。

## 页面归属与活动页面

组件展示所属页面的状态，导航操作查询调用时的活动页面。两者不能互相替代。

| 需求 | 使用方式 |
| --- | --- |
| 导航标题、底栏选中项、页面尺寸 | 在 setup 中通过 `usePageRoute()` 获取所属页面的固定路由 |
| 点击时判断当前活动页 | 调用 `usePages().getCurrentPage()` 读取真实页面栈 |
| 页面配置查询与导航操作 | 使用 `usePages()` 的查询、前进、返回及首页方法 |

缓存页离场后仍拥有自己的标题与选中项，异步组件挂载时也可能已有其他页面处于活动状态。因此，渲染状态应根据组件所属路由计算，不能在挂载时用栈顶路由替代。

`getCurrentPage()` 是即时查询，空栈时返回 `undefined`。它不提供响应式页面栈，也不需要应用级同步插件；如果界面需要持续追踪活动路由，应明确订阅对应事件，不能依赖没有响应式来源的 `computed` 缓存。

## 导航栏与底栏职责

顶部导航和底栏独立配置。`navigationStyle: 'default'` 使用平台导航栏，标题、返回控件和顶部空间由平台处理；`navigationStyle: 'custom'` 则由页面容器提供导航内容，并处理状态栏高度与平台胶囊避让。

项目的 `default` 布局在需要自定义导航时接入通用 `Navbar`；`tabbar` 布局把顶部内容交给页面。无论使用哪种布局，都应为导航内容保留准确占位，避免页面再次增加相同的顶部内边距。

`THEME_CONFIG.tabbar.mode` 选择原生或自定义底栏。原生底栏由平台渲染，自定义底栏由 `AppPageTabbar` 接入；具体组件通过页面接入层的显式导入选择。切换组件时应保留所属路由、导航结果和生命周期处理，接口约定见 [TabBar 接入与组件契约](tabbar.md)。

## 主 tab 页与子页

主 tab 页由页面元信息中的 `tabBar` 声明，页面插件汇总为 `pages.json` 的 `tabBar.list`。列表值使用稳定的页面路径，顺序、文字和图标由页面配置提供。

- 主 tab 页通过 `switchTab` 切换，不提供返回与首页胶囊
- 普通子页通过 `navigateTo` 打开，可传递查询参数
- 自定义导航子页由默认布局提供返回、首页按钮，返回使用 `goBack(true)` 处理栈不足和返回失败
- 原生导航子页使用平台控件，不额外叠加自定义导航栏

`go()`、`goHome()` 和 `goBack()` 返回 `Promise<boolean>`，表示导航 API 的结果，不表示目标页已经显示或转场已经结束。需要在目标页显示后操作组件时，应使用页面生命周期与实例就绪机制。

## 分包归属

主 tab 页在主包保留薄入口，负责路由元信息、布局选择与跨包组件占位。普通子页、业务视图、状态模块、专属样式和资源归属于各自分包，通用页面容器、导航与平台适配留在公共层。

主包入口通过静态导入引用分包视图，并在 `defineOptions()` 中声明 `componentPlaceholder`。在小程序端，插件将该声明写入页面 JSON，由平台在组件就绪前显示占位。组件的异步加载不能改成 Vue 文件的 `import()`；本项目的优化插件会屏蔽小程序端这种动态导入。

包内依赖使用显式导入，状态消费者指向同一个模块。主包薄入口应通过组件接口使用业务能力，避免直接导入包内数据与状态。模块的实际产物归属由依赖图决定，移动源码目录并不保证它会单独进入分包。

普通分包可以复用主包公共模块。共享状态不应因迁移而复制成多个实现，也不应通过临时读取本地存储代替内存中的响应式共享。若引入独立分包，需要另行设计其初始化与公共依赖，不能直接沿用普通分包的假设。

包内图片通过模块导入交给构建工具解析路径，避免将小程序产物路径直接用于 H5 开发服务。验证资源时应确认响应类型与图片实际加载结果，开发服务的页面回退也可能返回 HTTP 200。

构建后检查以下结果：

- 生成的分包根与页面路径正确，主 tab 路径仍指向主包
- 主包页面 JSON 包含分包组件引用和对应占位，页面 JS 未直接同步加载包内业务实现
- 包内共享状态在产物中只有一个定义，各消费者指向同一模块
- 专属图片保留分包静态路径，公共底栏图标仍由主包提供
- 分包专用样式进入对应页面或组件样式，应用级样式不包含这些专用类

## 安全区、高度与滚动

`PageWrapper` 统一计算页面可用高度，`useLayout()` 根据所属页面配置提供导航栏、底栏及内容区尺寸。高度单位为 px。

顶部只由一个层级负责：原生导航使用平台窗口偏移，自定义导航在容器内部占据状态栏和导航栏高度。自定义导航中的可点击区域还需避开微信右侧胶囊，不能仅按标题居中推断其可用宽度。

底部安全区与底栏高度也应分别计算。微信原生底栏页面的可用视口已排除底栏及安全区，容器直接填满该视口；自定义底栏和普通页面由容器预留底部安全区。H5 使用框架窗口偏移变量，其中已包含安全区，不能再次扣减。

H5 优先使用 `100dvh` 跟随可见视口变化，不支持时回退到 `100vh`。页面内的自定义底栏相对容器底部定位，默认保留同高占位；浮起组件可将顶部装饰覆盖到内容边缘，实际占位等于视觉高度减去覆盖量。`--tabbar-height` 表示完整视觉高度，原生底栏页和普通页面为零。

`useLayout().pageHeight` 扣除完整底栏高度，表示避开全部底栏装饰的保守内容高度。实际滚动区域由弹性布局分配；需要精确尺寸时应测量滚动容器，不能用该值替代。

内容区域使用可收缩的纵向布局，通过 `flex: 1` 和 `min-height: 0` 分配剩余高度。确定一个主要滚动区域，并让导航栏、底栏占位保持稳定；使用 `scroll-view` 时应使其高度受容器约束，避免内容把页面整体撑开，或与外层形成重复滚动。

## 框架默认样式覆盖

应用级颜色变量与元素重置放在 `src/styles/base.scss`，由 `App.vue` 引入。分包专用样式由实际使用它们的页面或组件通过 `scoped` 样式显式引入，避免仅移动文件后仍从应用入口全局加载。

组件的 `scoped` 样式只覆盖自身模板。共享类名在多个组件中使用时，每个使用方都应引入对应样式，不能依赖父组件的作用域规则穿透子组件。

H5 开发服务按需注入组件样式，构建产物则统一加载 CSS，两者的加载顺序可能不同。覆盖框架默认样式时，应使用范围明确、优先级足够的选择器，避免依赖同优先级规则的先后顺序。

例如，页面按钮重置使用 `page button` 和 `page button::after`，既优先于框架的单标签规则，又允许组件类名继续覆盖。按钮默认边框由伪元素提供，需要单独处理。验证时应同时检查开发服务与构建预览，并比较浏览器实际采用的样式。

## 测试入口边界

交互与组件测试集中在独立入口，主页面只提供跳转。测试页面应展示操作条件、执行状态和可核对的结果，不依赖控制台才能判断是否成功。

分包测试的目录位置属于验证条件。主包调用分包组件的场景，应保留主包页面、分包组件、`componentPlaceholder` 和实例就绪等待；把调用方移入同一个分包，会改变被测的加载边界。

生命周期测试应区分首次挂载、再次显示和卸载。异步调用需要避免重复触发，并在页面销毁后停止更新结果。参数测试应编码跳转参数，覆盖读取与返回；状态测试应明确状态属于当前页面、共享存储还是本地持久化。

页面操作用于验证真实流程，组件契约与回归行为由自动化测试覆盖。原生导航、设备安全区和小程序页面交接仍需结合目标平台确认。
